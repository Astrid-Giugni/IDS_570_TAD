    Step 2b: Does the Clustering Survive a Different Representation?

    In Step 2 we clustered the raw 768-dimensional embeddings and used UMAP only to draw the picture. That is a sound default. But it is not the only defensible choice: many researchers normalize their embeddings and reduce them with PCA before clustering, to strip out noise and to deal with the fact that raw BERT vectors are crowded into a narrow region of the space (they are “anisotropic”; see Ethayarajh 2019).

    Because our corpus is small, K-Means is cheap, so we don’t have to pick one approach on faith: we can run it both ways and compare. If the clusters are the same, our Step 2 result does not depend on that preprocessing choice. If they differ, the documents that move are worth reading.

    We compare three pipelines, keeping k the same as in Step 2:

    • A: raw, full 768-d. Exactly what Step 2 did (this should reproduce your Step 2 labels).
    • B: normalized, full 768-d. Each vector is scaled to length 1 (L2 normalization), so K-Means’ Euclidean distance behaves like the cosine similarity we have used all semester.
    • C: normalized + PCA-50. As B, then reduced to 50 principal components before clustering.

    We measure three things:

    1. Agreement between pipelines with the adjusted Rand index (ARI): 1 means the two partitions are identical; values near 0 mean they agree no more than chance would. ARI ignores the arbitrary cluster numbers (Cluster 0 in one run can be Cluster 1 in another).
    2. Silhouette, computed two ways: in each pipeline’s own space, and in one common reference space (the normalized full embeddings). Only the second column is comparable across pipelines: silhouettes computed in different spaces are on different scales.
    3. Stability across random seeds: K-Means starts from random centroids, so we rerun each pipeline with five seeds and check how much the result changes.

    Finally, we list the documents that change cluster between A and C, and plot both clusterings on the same 2-D projection, so that any difference you see comes from the labels and not from the picture.

    Create a new file, step2b_robustness_check.py, and run it:

    import json
from itertools import combinations
from pathlib import Path

import numpy as np
import matplotlib.pyplot as plt
import matplotlib
from scipy.optimize import linear_sum_assignment
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.metrics import adjusted_rand_score, silhouette_score
from sklearn.preprocessing import normalize

matplotlib.rcParams["figure.dpi"] = 150

N_PCA = 50                  # number of principal components for pipeline C
SEEDS = [0, 1, 2, 3, 4]     # seeds for the stability check

# Load the Step 1 embeddings and the Step 2 cluster labels
with open(Path("data") / "doc_embeddings.json", "r") as f:
    data = json.load(f)
X_raw = np.array(data["embeddings"])
filenames = data["filenames"]

with open(Path("data") / "cluster_assignments.json", "r") as f:
    step2 = json.load(f)
K = step2["K"]                                  # same k as Step 2
step2_labels = np.array(step2["cluster_labels"])
assert step2["filenames"] == filenames, "Files are not in the same order as Step 2!"

print(f"{len(X_raw)} documents, {X_raw.shape[1]} dimensions, k = {K}")

# Build the three representations. SEE [1] below
X_norm = normalize(X_raw)                       # L2: every vector now has length 1
pca = PCA(n_components=N_PCA, random_state=42)
X_pca = pca.fit_transform(X_norm)
print(f"PCA-{N_PCA} keeps {pca.explained_variance_ratio_.sum():.1%} of the variance")

spaces = {
    "A: raw, full 768-d": X_raw,
    "B: normalized, full 768-d": X_norm,
    f"C: normalized + PCA-{N_PCA}": X_pca,
}

def run_kmeans(X, seed):
    return KMeans(n_clusters=K, random_state=seed, n_init=10).fit_predict(X)

labels = {name: run_kmeans(X, 42) for name, X in spaces.items()}

# Sanity check: pipeline A should reproduce Step 2 exactly
print(f"\nARI, pipeline A vs. Step 2 labels: "
      f"{adjusted_rand_score(step2_labels, labels['A: raw, full 768-d']):.3f} (should be 1.000)")

# 1. Agreement between pipelines. SEE [2] below
print("\n=== Agreement between pipelines (adjusted Rand index) ===")
for a, b in combinations(spaces, 2):
    print(f"  {a}  vs.  {b}:  ARI = {adjusted_rand_score(labels[a], labels[b]):.3f}")

# 2. Silhouette in each pipeline's own space and in one common space. SEE [3] below
print("\n=== Silhouette scores ===")
print(f"  {'pipeline':<30}{'own space':>12}{'common space':>15}   cluster sizes")
for name, X in spaces.items():
    own = silhouette_score(X, labels[name])
    common = silhouette_score(X_norm, labels[name])
    sizes = sorted(np.bincount(labels[name]).tolist(), reverse=True)
    print(f"  {name:<30}{own:>12.3f}{common:>15.3f}   {sizes}")

# 3. Stability across random seeds
print("\n=== Stability across seeds (mean ARI between runs) ===")
for name, X in spaces.items():
    runs = [run_kmeans(X, s) for s in SEEDS]
    pair_aris = [adjusted_rand_score(r1, r2) for r1, r2 in combinations(runs, 2)]
    print(f"  {name:<30} mean ARI = {np.mean(pair_aris):.3f}  (min {np.min(pair_aris):.3f})")

# 4. Which documents change cluster between A and C? SEE [4] below
def align(reference, other, k):
    """Relabel `other` so its cluster numbers match `reference` as closely as possible."""
    table = np.zeros((k, k), dtype=int)
    for r, o in zip(reference, other):
        table[r, o] += 1
    rows, cols = linear_sum_assignment(-table)
    mapping = {o: r for r, o in zip(rows, cols)}
    return np.array([mapping[o] for o in other])

labels_A = labels["A: raw, full 768-d"]
labels_C = align(labels_A, labels[f"C: normalized + PCA-{N_PCA}"], K)
moved = np.where(labels_A != labels_C)[0]

print(f"\n=== Documents that change cluster between A and C: {len(moved)} ===")
for i in moved[:25]:
    print(f"  {filenames[i]}:  cluster {labels_A[i]} (A)  ->  cluster {labels_C[i]} (C)")
if len(moved) > 25:
    print(f"  ... and {len(moved) - 25} more (all saved to data/robustness_moved_docs.json)")

# 5. Plot both clusterings on the SAME 2-D projection. SEE [5] below
try:
    import umap
    reducer = umap.UMAP(n_components=2, random_state=42, n_neighbors=15, min_dist=0.1)
    coords = reducer.fit_transform(X_norm)
    method = "UMAP"
except ImportError:
    coords = PCA(n_components=2).fit_transform(X_norm)
    method = "PCA"

fig, axes = plt.subplots(1, 2, figsize=(16, 7), sharex=True, sharey=True)
cmap = plt.cm.Set2
for ax, (title, lab) in zip(axes, [("A: raw, full 768-d", labels_A),
                                   (f"C: normalized + PCA-{N_PCA}", labels_C)]):
    for c in range(K):
        mask = lab == c
        ax.scatter(coords[mask, 0], coords[mask, 1], c=[cmap(c)], s=25, alpha=0.6,
                   edgecolors="black", linewidths=0.2, label=f"Cluster {c} (n={mask.sum()})")
    ax.scatter(coords[moved, 0], coords[moved, 1], marker="x", c="black", s=40,
               label=f"moved between A and C ({len(moved)})")
    ax.set_title(f"Clustered on: {title}")
    ax.set_xlabel(f"{method} Dimension 1")
    ax.legend(loc="upper right", fontsize=8)
axes[0].set_ylabel(f"{method} Dimension 2")
plt.suptitle(f"Same {method} projection, two clusterings (k={K})")
plt.tight_layout()
plt.savefig("robustness_check.png", dpi=150, bbox_inches="tight")
plt.show()

# Save results
output = {
    "K": K,
    "n_pca": N_PCA,
    "labels_A_raw": labels_A.tolist(),
    "labels_C_norm_pca_aligned": labels_C.tolist(),
    "moved_filenames": [filenames[i] for i in moved],
}
with open(Path("data") / "robustness_moved_docs.json", "w") as f:
    json.dump(output, f, indent=2)
print("\nSaved plot to robustness_check.png and results to data/robustness_moved_docs.json")

    [1] normalize rescales every document vector to length 1, so only its direction matters, as with cosine similarity. PCA then keeps the 50 directions along which the documents vary most. The script prints how much of the variance those 50 components keep. If it seems low, try N_PCA = 100, or PCA(n_components=0.90) to keep however many components reach 90% of the variance. Note that with about 620 documents, PCA can find at most about 620 components, however many dimensions BERT gives us.

    [2] The ARI compares two ways of grouping the same documents. It does not care what the clusters are called, only who is grouped with whom.

    [3] Why two silhouette columns? A silhouette computed in PCA space and one computed in the raw space are measured with different rulers, so the “own space” numbers cannot be compared across rows. The “common space” column scores every pipeline’s grouping in the same (normalized, full) space, so those numbers can be compared.

    [4] Because cluster numbers are arbitrary, we first relabel C’s clusters to match A’s as closely as possible (align), and only then ask which documents differ.

    [5] We compute one projection and color it twice. If we made a separate UMAP for each pipeline, differences between the two pictures could come from UMAP itself rather than from the clustering.

    What to look for

    • Sanity check: pipeline A vs. Step 2 should print ARI = 1.000. If it doesn’t, the file order or k has changed since Step 2.
    • If the ARIs between pipelines are close to 1 and few documents move: the split we found in Step 2 does not depend on normalization or PCA. That makes it a more trustworthy result, and it is worth one sentence when you report it.
    • If they disagree: don’t just pick the pipeline you like better. Read the documents that moved (the list above). Are they borderline cases, very short or very long documents, duplicates, or texts with unusual spelling? The disagreement is itself a finding about your corpus.
    • Stability: a pipeline whose own runs disagree with each other (low mean ARI across seeds) is not a stable basis for interpretation, whatever its silhouette.

    My results: The genre split from Step 2 does not depend on preprocessing: raw, normalized, and normalized + PCA-50 embeddings all produce the identical 525 / 97 partition (ARI = 1.000), stable across five random seeds, and no document changes cluster. Robustness to preprocessing does not by itself make the split meaningful, which is why Step 3 reads the clusters, but it means the split is not an artifact of how we prepared the vectors.
